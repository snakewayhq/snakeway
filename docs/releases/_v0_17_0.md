This release adds editor support for Snakeway configuration and changes some configuration settings.
Read the upgrading section before you deploy.

{/* truncate */}

## Highlights

- Your editor can check Snakeway configuration as you type.
  See [Editor Support](/docs/administration/editor-support).
- Services and WASM devices have names.
- Snakeway no longer needs OpenSSL.

## Added

- The `snakeway lsp` command for editor support.
- Block labels for `services` and `wasm_devices`, such as `services "api" { ... }`.
- A `tls` block for Unix socket upstreams.
- `GET /admin/reload`, which shows how the last reload finished.

## Changed

- Every service needs a name.
- In WASM devices, `timeout_ms` is now `timeout_milliseconds`, and `body_buffer_max` is now `body_buffer_max_bytes`.
- A Unix socket upstream is now written as `sock = { path = "/run/app.sock" }`.
- A Unix socket upstream uses TLS only when it has a `tls` block.
- A repeated key in a WASM device `config` block is now an error.
- A CA file must contain only certificates.
- Upstream certificate checks are stricter.
  See [Certificate requirements](/docs/configuration/ingress/upstream-tls#certificate-requirements).
- Configuration errors show the line from your file where the problem is.
- A reload that changes `pid_file` or `upgrade.sock` is rejected.
  Restart Snakeway to apply those changes.

## Fixed

- Two services under one `bind` now both receive traffic.
- A reload now picks up manual TLS certificate files that you replaced.
- A reload now applies changes to server settings such as upstream timeouts and `ca_file`.
  This starts a new process and works only on Linux with a `pid_file`.

## Security

- An upstream with `verify = true` and no CA file now has its certificate checked.
  Before this release, Snakeway did not check it.

## Known issues

- `upgrade.max_retries` has no effect.
  The listener handover during a zero-drop upgrade always retries five times.
  A fix is open at https://github.com/cloudflare/pingora/pull/1012.

## Upgrading

After you install v0.17.0, run `snakeway config check` on your configuration.
It reports the settings that you need to change.

- Give every service a name, with a block label or a `name` attribute.
- In WASM devices, rename `timeout_ms` to `timeout_milliseconds` and `body_buffer_max` to `body_buffer_max_bytes`.
- Change each `sock = "/path"` to `sock = { path = "/path" }`.
  If the socket uses TLS, add a `tls` block.
- Remove anything that is not a certificate from your CA files.
- If an upstream sets `verify = true` and uses a certificate from a private CA, set `ca_file` for that upstream.
