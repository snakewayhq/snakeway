This release moves configuration feedback into your editor and gives services and WASM devices real names.
`snakeway lsp` serves every configuration file from one editor registration, repeated blocks carry native HCL labels, and the configuration layer moved from confval 0.7.3 to 0.9.0.
Two configuration keys were renamed and one was added, so read the upgrading section before deploying.

## Highlights

- The `snakeway` binary now ships a language server. Register `snakeway lsp` once in your editor and every Snakeway config file gets diagnostics, completion, hover, and navigation, with the schema chosen per file from your own `include` globs. See [Editor Support](/docs/administration/editor-support).
- Services and WASM devices are named with native HCL block labels: `services "api" { ... }` and `wasm_devices "auth" { ... }`. The plain `name` attribute form is also accepted. A service's name is its real identity, unique across the whole configuration.
- Field constraints are declared on the spec fields themselves, so ranges and keyword sets now surface in editor hover and completion, and every constraint is enforced by the same declaration the editor reads.

## Added

- The `snakeway lsp` subcommand, a Language Server Protocol server over standard input and output. One process serves the entrypoint, device documents, and ingress documents, routing each file by the `include` globs of the nearest `snakeway.hcl`, with the conventional `device.d` and `ingress.d` layout served before an entrypoint exists.
- An [Editor Support](/docs/administration/editor-support) page covering registration, routing, and the checks that stay outside the editor.
- Native HCL block labels on `services` and `wasm_devices`, with completion and go to definition support in the editor.
- The `name` field on services. Every service requires one, and a duplicate name across ingress files is a configuration error.
- Label checks at load time: a duplicate label and an empty label in a document are reported with both declaration sites attached.

## Changed

- A `services` block requires a `name`, written as a block label or as an attribute. The name replaces the previous internally derived identity.
- Two WASM device fields follow the full unit name convention: `timeout_ms` is now `timeout_milliseconds`, and `body_buffer_max` is now `body_buffer_max_bytes`.
- Diagnostics render in the rustc style, with the source line, an underline, and related spans. Update anything that matches the old rendering, such as tooling that parsed `-->` markers.
- A repeated key in a WASM device `config` block is a configuration error rather than a silent overwrite. The inline object form, `config = { ... }`, still keeps the last value, pending an upstream parser fix.
- A bad entry in a keyword list reports as `unknown value in events: reloded` at the entry's own span, in place of the previous `unknown event: reloded` shape.
- The populated views of `config dump` include a WASM device's `config` map even when it is empty.
- The configuration layer migrated from confval 0.7.3 to 0.9.0.

## Fixed

- Two services under one bind no longer collapse into a single routing entry. Their identities previously derived to the same value, so the second service silently replaced the first. Named services make the collision impossible, and a duplicate name is reported instead.

## Upgrading

Run `snakeway config check` against your configuration before upgrading.
Two changes require editing existing configuration files.

1. Name every service. Add a block label, `services "api" { ... }`, or a `name = "api"` attribute inside the block. Names must be unique across all ingress files.
2. Rename the WASM device fields: `timeout_ms` becomes `timeout_milliseconds`, and `body_buffer_max` becomes `body_buffer_max_bytes`. A file with the old names fails to parse, and the error names the unknown field.

Two output changes can affect tooling.
Diagnostics render in the rustc style, so update anything that matched the old format.
Keyword list errors changed shape to `unknown value in <field>: <entry>`, so update anything that matched the old messages.

After upgrading, register the language server in your editor.
The [Editor Support](/docs/administration/editor-support) page has the setup.
