## Fixed

- A single request with a malformed percent encoding next to a multibyte character in the query string, such as `/api?%%é`, no longer crashes the proxy.
  The query decoder now works on bytes, rejects the malformed sequence, and forwards raw multibyte characters in the query unchanged.
  Before this release, such a request panicked the worker thread, which aborts the whole process in the release build, and raw multibyte query values were silently rewritten as Latin 1 mojibake.
- A `Range` request against a static file that is truncated or partially rewritten while it is being served no longer crashes the proxy.
  The served range is now fitted to the bytes actually read.
  Before this release, the validated range was sliced against a buffer that could be shorter than the range, which panicked the worker thread and aborts the process in the release build.
- The device pipeline now always runs in a fixed canonical order: request filter, identity, network policy, rate limiting, WASM devices, then structured logging.
  Before this release, the pipeline ran in configuration file order, so a network policy or rate limiting device whose file sorted before the identity device was silently ignored, because it ran before the request had an identity.
  Configurations that relied on file name order should verify their device behavior after upgrading.
- A unix socket upstream path longer than the operating system limit is now rejected by `snakeway config check` with an error that names the limit.
  Before this release, such a configuration passed validation, started, and then failed every request with `http peer creation failed`.
