## Fixed

- A single request with a malformed percent encoding next to a multibyte character in the query string, such as `/api?%%é`, no longer crashes the proxy.
  The query decoder now works on bytes, rejects the malformed sequence, and forwards raw multibyte characters in the query unchanged.
  Before this release, such a request panicked the worker thread, which aborts the whole process in the release build, and raw multibyte query values were silently rewritten as Latin 1 mojibake.
- A `Range` request against a static file that is truncated or partially rewritten while it is being served no longer crashes the proxy.
  The served range is now fitted to the bytes actually read.
  Before this release, the validated range was sliced against a buffer that could be shorter than the range, which panicked the worker thread and aborts the process in the release build.
- The device pipeline now always runs in a fixed canonical order: request filter, identity, network policy, rate limiting, WASM devices, then structured logging.
  Before this release, the pipeline ran in configuration file order, so a network policy or rate limiting device whose file sorted before the identity device was silently ignored, because it ran before the request had an identity.
  Configurations that relied on file name order should verify their device behavior after upgrading.
- A unix socket upstream path longer than the operating system limit is now rejected by `snakeway config check` with an error that names the limit.
  Before this release, such a configuration passed validation, started, and then failed every request with `http peer creation failed`.
- `snakeway config check` now validates route paths the way the proxy does.
  A static route path without a leading slash, a service route path without one, and duplicates across service and static routes are all reported at check time instead of failing at startup or on every later reload.
- An ingress file that declares services or static files under a `bind_admin`-only listener now warns at check time that those entries are ignored.
  Before this release, they were dropped silently and the check reported success.
- Redirect listener uniqueness is now checked per address, not per port.
  Two binds on different interfaces may share a redirect port, and a redirect port that collides with a bind or admin port on the same address is rejected instead of binding two listeners on one socket.
- A reload that changes `ws_max_connections` now takes effect for new connections, and websocket routes that leave the configuration are cleaned out of the admin statistics once their connections drain.
  Before this release, the limit was fixed at the first connection and removed routes were reported forever.
- A half-open circuit probe whose request never started now returns its slot.
  Before this release, a failure between selection and peer build could leave the circuit unable to admit any probe until a reload or restart.
- A failed request attempt no longer finalizes the previous attempt's guard as a success.
  Before this release, a retry after a transport failure could mark a dead upstream healthy and even close a half-open circuit on it.
- An upstream whose health cooldown has expired stays admissible on every decision until an outcome lands.
  Before this release, each decision that did not select the upstream restarted its cooldown, so with failover a dead primary delayed recovery by up to a full cooldown.
- An ACME bind with the HTTP-01 challenge now requires a `redirect_http_to_https` block, which is the only listener that serves the challenge.
  Before this release, such a configuration passed validation and its certificate could never issue, leaking challenge tokens on every retry.
- `on_response` devices now run before a static file response is written, so their header and status mutations apply.
  Before this release, the pipeline ran after the response was already on the wire and its result was discarded.
- Reloads and DNS refreshes no longer block the single worker control runtime on WASM compilation, hostname resolution, and file reads.
  A stalled resolver now delays only its own lookup, bounded by a timeout, instead of stalling reload outcomes, signal handling, and certificate renewal together.
